# Feedback and Feature Requests

QuietPlay's public repository hosts downloads, documentation, and listener
feedback. The app's development workspace is private. You do not need coding
experience to help improve the app, and submitting an issue does not grant
write access to its files.

## Pick the Right Form

| What You Need | Where to Go |
| --- | --- |
| A new feature or a better workflow | [Feature request](https://github.com/cooperwwwwww/QuietPlay-downloads/issues/new?template=feature_request.yml) |
| Something broken, slow, or visually incorrect | [Bug report](https://github.com/cooperwwwwww/QuietPlay-downloads/issues/new?template=bug_report.yml) |
| Help installing or configuring the app | [Setup question](https://github.com/cooperwwwwww/QuietPlay-downloads/issues/new?template=help.yml) |

Search existing issues first. A reaction or a useful example on an existing
request is better than several copies of the same idea. Keep each issue focused
on one problem; separate unrelated ideas so their progress can be tracked.

## Make a Useful Request

Explain what you were trying to do, what currently makes it awkward, and how
your idea would help. A quick sketch or cropped screenshot is welcome but not
required. Requests are reviewed for usefulness, performance impact, reliability,
and whether they fit QuietPlay. Submission is not a promise of implementation.

## Make a Useful Bug Report

Include the version from **Settings > Updates**, your Windows version, steps
to reproduce, and what you expected instead. For playback problems, say whether
the file is local or newly downloaded and whether shuffle is enabled. For UI
problems, include the screen size and display scaling if you know them.

Do not attach your music library or complete diagnostic files automatically.
If a maintainer asks for a small diagnostic excerpt, review it first and remove
private paths, account details, credentials, and unrelated information.

## Keep Feedback Public-Safe

Issues and comments can be read by anyone. Do not post passwords, tokens,
personal contact details, OBS connection secrets, music files, or screenshots
containing private information. Report accidental exposure to the repository
owner through a private channel rather than repeating the sensitive content
in another public issue.

Be constructive and describe the behavior, not the person. Do not use issues
for music uploads, spam, or requests to bypass Windows protections or music
provider access controls.

## Status Labels

| Label | Meaning |
| --- | --- |
| `needs triage` | New feedback awaiting review; not yet confirmed. |
| `feature request` | A suggested improvement or new capability. |
| `bug` | A report that something may not be working correctly. |
| `question` | Installation or usage help. |
| `needs info` | More details are needed to investigate. |
| `planned` | The maintainer has accepted a scope; no release date is implied. |
| `in progress` | Work is underway, but it is not yet released. |
| `duplicate` | Another issue tracks the same request. |

Only the maintainer assigns workflow labels. A closed issue is not always a
shipped feature: read its resolution and the changelog. Released changes are
listed in versioned [release notes](https://github.com/cooperwwwwww/QuietPlay-downloads/releases).
